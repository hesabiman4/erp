# Implementation decisions

- 2026-10-28: Empty repository apart from the master specification. Preserve that specification as the authoritative scope.
- Use Django 5.2 LTS, DRF, React/TypeScript/Vite, PostgreSQL 18. Dependencies are resolved and locked to actual installed compatible releases.
- Local verification uses an isolated PostgreSQL cluster under .local/pgdata on loopback port 55432. The stopped system PostgreSQL service and Docker are not altered.
- Stock quantity precision is six decimal places; geometry is mm with three decimal places. Monetary movement values round HALF_UP to cents; moving averages retain precision until an issue is valued. This keeps stock value and journal control accounts reconciled.
- Initial concurrent posting locks the business row plus affected stock pools. This prioritizes correct low-volume manufacturing transactions; narrower lock partitioning requires measured load and regression tests.
- Valuation pool = business + warehouse + product + compatible footprint. Same weighted-average policy everywhere; transfer carrying value is frozen through transit.
- Internal branch charges are a management subledger attached to stock transfers. They never enter customer revenue or receivables.
- Public deployment is outside current authorization. Real tax settings, legal entity mapping, production overhead policy, and real opening balances require owner/accountant configuration before go-live.
- Original baseline excluded multi-currency/Jalali. The authorized competitive extension now supplies shared Jalali dates and AFN-functional USD/PKR monetary tracking, settlement and revaluation, with explicit limits in OPERATIONS_AND_CURRENCY.md. Partial-footprint cuts, offline final posting, historical cost replay and full intercompany consolidation remain unavailable. Actual production and optional-per-business BOM production remain core requirements.
- 2026-10-30: Owner chose to configure the encrypted backup destination later. Scheduled backups remain not_configured; no invented external path or off-device recovery claim.
- 2026-10-30: Foreign invoice registration must match an unpaid original AFN document at the exact contractual rate. Functional ledger amounts are never reinterpreted as foreign amounts; linked monetary movement ledgers carry settlement/revaluation history. Foreign corrections remain blocked until a conservative linked design is implemented.

- 2026-10-30 calendar refinement: the requested default is Jalali, using Afghan month names and a shared authenticated month-grid endpoint. Migration 0013 resets prior calendar preferences once. Dates remain canonical Gregorian; accounting-month/payroll boundaries are not silently redefined. Period controls show actual translated date ranges.
- Employee statements keep credit-positive salary payable and debit-positive advances in separate ledgers. Gross earnings, actual cash/bank settlement and advance recovery are independent figures; pagination computes running balances before slicing.
- Beginner account guidance is checked against all 62 default account codes and 96 registered operation identifiers. Non-control chart templates do not imply missing loan/lease/tax/owner-cash workflows are implemented.

- 2026-11-02: New business calendar changes are prospective explicit contract policies; per-user display preferences never silently change payroll or ledger history. Capacity estimates reserve daily work-center minutes but do not imply material/staff feasibility. Loss thresholds are optional operator review choices. Customer proposals are immutable nonfinancial portal records reviewed into real staff documents; messages distinguish provider acceptance from staff-reviewed delivery evidence. Restricted blind counters have a separate record permission, protected snapshots and independent adjustment. Scale integration is calibrated manual confirmation until a specific physical device is integrated and verified. Shared/unattributed profit costs remain visible rather than guessed allocations.

- 2026-11-02 v5: Task profiles grant no permission; learning completion is personal progress rather than accounting approval. Full-page documents retain tenant-bound deep links and server source checks. Production drag-and-drop opens reviewed existing operations; accounting/stock are never changed by a cosmetic stage move. Local OCR preserves the private source and explicit human-reviewed ordinary draft. Exact source duplicates and supported supplier references are blocked; unknown fields are left blank. Staff/native-device acceptance remains a real human activity, with an unfilled checklist supplied.

- 2026-11-03 localization: retain Dari as primary/fallback and the existing l()/i18next catalogs. Translate static captions, controlled-option labels and fixed server explanations; preserve stored enum values, source names, original evidence and free-text notes. Author full Pashto lesson bodies without changing step IDs/version/progress. Apply document language/direction at the application boundary so login and customer-only portal sessions also work in English LTR and Dari/Pashto RTL. Source coverage audits and real browser checks are complementary: neither is native editorial certification, and backend/Django/provider diagnostics plus a Pashto PDF remain separate scope.
